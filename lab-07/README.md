# Лабораторная работа № 7. Базовый поиск афиш

Проект — поиск афиш по текстовому описанию. Исполнитель — Мирута Александр Владиславович, МИК22.

TF-IDF с косинусным сходством даёт воспроизводимую точку отсчёта для следующего варианта поиска. Вход модели — текст запроса и `description` карточек. Такой подход использует готовые текстовые описания и позволяет показать, какое слово привело карточку в выдачу. Вес слова равен частоте в тексте, умноженной на IDF, после чего вектор нормируется по L2. Модель использует токенизацию и подсчёт IDF из ЛР № 6. [Описание TF-IDF](https://scikit-learn.org/stable/modules/feature_extraction.html#tfidf-term-weighting)

## Запуск

Выполните из корня репозитория. Нужен Python 3.10 или новее. Достаточно стандартной библиотеки и файлов набора, уже сохранённых в репозитории.

```bash
python3 lab-07/baseline.py evaluate
python3 lab-07/baseline.py search "джаз минимализм"
python3 lab-07/baseline.py search "саксофон насыщенный"
python3 -m unittest discover -s lab-07 -p 'test_*.py' -v
```

`evaluate` создаёт файлы в `lab-07/results/`. `search` печатает результат разового запроса по каталогу validation. Пустой запрос даёт `empty_query`, запрос без слов из словаря даёт `no_known_terms`. В обоих случаях список результатов пуст.

## Фиксированные условия

Параметры сохранены в [settings.json](settings.json). Версия набора 1.2 привязана к [коммиту ЛР № 6](https://github.com/LimeGoodGame/poster-search/tree/56cb62f37f22279749c5e355d75ca053aea376d4/lab-06/data). При запуске проверяются SHA-256 манифеста, входных файлов и кода предобработки. Словарь и IDF повторно вычисляются по 12 допущенным карточкам train, затем сверяются с зафиксированными весами ЛР № 6. Каталог оценки содержит 12 допущенных карточек validation. Данные test исключены из расчёта IDF, выдачи и метрик.

| Параметр | Значение |
|---|---|
| Словарь и IDF | 12 токенов из train. Для слова с частотой документов `df` вес равен `ln((1 + N) / (1 + df)) + 1`, где `N = 12`. |
| Признаки | Только `description` и текст запроса. `rights_status` служит фильтром допуска, ID разрешает ничьи. Жанр и стиль используются в разборе результатов, автор и путь относятся к метаданным. |
| Запросы и каталог | 12 запросов и 12 карточек validation. По 12 оценок релевантности на запрос. |
| Ранжирование | Выдача содержит до трёх результатов с положительным косинусом. Сортировка по убыванию полной оценки, затем по ID. |
| Обработка слов | NFKC, `casefold`, выделение буквенно-цифровых токенов. Вес имеют только токены из train. Замены синонимов не применяются. |
| Случайность | Отсутствует. Seed не требуется. |
| Окружение | Фактические версия Python и SHA-256 настроек сохранены в [environment.json](results/environment.json). |

Для `nDCG@3` выгода карточки с оценкой `g` равна `2^g − 1`, дисконт на позиции `i` равен `1 / log₂(i + 1)`. Идеальный порядок рассчитывается из всех оценок каталога. `Recall@3` делит число возвращённых карточек с оценкой 1 или 2 на полное число таких карточек в каталоге. Пустая выдача даёт ноль по обеим метрикам. Итог — среднее по запросам. Пример считается удачным, если первый ответ имеет оценку 2 и обе релевантные карточки попали в top-3.
