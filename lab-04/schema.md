# Схема данных

Версия 1.1 от 22.11.2026. Единица анализа — один макет афиши. Варианты одного макета, автора, серии и геометрического семейства должны целиком относиться к одной выборке. Карточки хранятся как список JSON-объектов в `data/raw.json` и `data/clean.json`.

## Карточка афиши

| Поле | Тип и допустимые значения | Назначение |
|---|---|---|
| `id` | Строка, уникальный код `P001`; контрольные коды `D001` и `X001` встречаются только в raw | Идентификатор и связь с разметкой |
| `description` | Непустая строка в clean | Текстовый вход для будущего TF-IDF |
| `genre` | `джаз`, `театр`, `кино`, `выставка`, `электроника`, `фестиваль` | Анализ сегментов и разметка |
| `style` | `минимализм` или `детализация` | Анализ сегментов и разметка |
| `author`, `series` | Вымышленные коды `A01`–`A06`, `S01`–`S06` | Группировка |
| `layout_family` | `L01`–`L06` | Контроль повторяющихся геометрических шаблонов |
| `group_id` | Составная строка вида `A01\|S01\|L01` | Назначение группы одному split |
| `split` | `train`, `validation`, `test` | Граница эксперимента |
| `source` | `generated:prepare_data.py@1.1` | Происхождение S01 |
| `rights_status` | `demo_allowed` или `unknown`; в clean только первый | Технический допуск |
| `synthetic` | Логическое `true` | Способ создания |
| `data_version` | Строка `1.1` | Версия |
| `width`, `height` | Положительные целые, 600 и 800 | Размеры SVG |
| `image` | Относительный путь к существующему SVG | Просмотр и проверка файла |
| `sha256` | 64 шестнадцатеричных символа | SHA-256 точных байтов UTF-8 файла SVG |

Все перечисленные поля обязательны. Пустой `description` и `unknown` допустимы в raw для контрольных дефектов, такие карточки исключаются при очистке. Проверяются существование SVG, его размеры и соответствие байтов хешу. Кодировка JSON и SVG — UTF-8.

Ранжирование предполагается только по `description` и тексту запроса. Жанр, стиль, автор, группа, split, источник и статус допуска остаются метаданными для аудита, разметки и ограничения каталога. Для текущих SVG вычисляется также хеш после удаления `<text>`-узлов, чтобы код карточки на изображении не скрывал повтор геометрии. Это частная проверка, она не обнаруживает все возможные визуально близкие изображения.

## Запрос и будущая разметка

В `data/queries.json` одна запись означает один запрос к каталогу своего split. Обязательные поля — уникальный `id`, `split`, непустой `text`, целевой `genre`, `preferred_style`, `kind`, `source` и `synthetic`. `kind` принимает `literal` или `synonym`. В версии 1.1 все запросы имеют `preferred_style=минимализм`, `synthetic=true`. Сведения о целевом жанре и стиле используются при проверке релевантности, в ранжировщик передаётся текст.

Для будущей разметки одна строка CSV будет означать пару «запрос — карточка». Поля — `query_id`, `poster_id`, `relevance` из множества 0, 1, 2, `annotator_id`, `status` из множества `draft`, `agreed`, `review`, и строка `comment`. Идентификаторы пары должны существовать, их split должны совпадать. Пустая или спорная оценка получает `review` и передаётся на обсуждение. Реальная экспертная разметка в ЛР № 4 не проводилась.

## Персональные и чувствительные данные

Реальных имён, лиц, контактов и персональных идентификаторов в наборе нет. `author` обозначает семейство генератора. Период реальных событий и география аудитории не заданы. При подключении студийного архива состав метаданных и основания их обработки нужно пересмотреть.
