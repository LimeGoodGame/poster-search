# Подготовка набора версии 1.2

Нужен Python 3.10 или новее. Скрипт работает со стандартной библиотекой. Из корня репозитория выполните команды.

```bash
python3 lab-06/prepare.py
python3 -m unittest discover -s lab-06 -p 'test_*.py' -v
```

Скрипт проверяет хеши исходной версии 1.1 и повторяет очистку из ЛР № 4. Сначала исключаются записи с неподтверждённым допуском, затем записи без описания и повторы байтов изображения. Полученные 36 карточек должны совпасть с исходным clean. Геометрия SVG проверяется по инструкции 1.0. Совпадение с прежними метками проверяется после подсчёта. При споре в пилоте сохраняется журнал и сборка останавливается до разбора. Файлы ЛР № 4 используются на чтение.

| Файл | Содержимое |
|---|---|
| [data/manifest.json](data/manifest.json) | Версии, количество объектов, контрольные суммы исходных артефактов пилота и результатов |
| [data/clean.json](data/clean.json) | 36 карточек со стилем, способом получения метки, группой и выборкой. Поле `image` отсчитывается от корня репозитория. |
| [data/queries.json](data/queries.json) | 36 синтетических запросов, по 12 на выборку |
| [data/qrels.csv](data/qrels.csv) | 432 оценки по шкале 0–2 для пар в пределах одной выборки |
| [data/idf.json](data/idf.json), [data/tfidf.json](data/tfidf.json) | Словарь и веса, рассчитанные по train, и разреженные векторы карточек и запросов |
| [results/exclusions.csv](results/exclusions.csv) | Причины исключения шести исходных записей |

## Границы оценки

Группы афиш и принадлежность к train, validation и test сохранены из ЛР № 4. Между частями проверяются ID, автор, серия, геометрическое семейство, составная группа, SHA-256 изображения и хеш SVG после удаления подписей.

Запросы версии 1.2 используют разные шаблоны для трёх частей. В каждой части по одному запросу на каждую пару из шести жанров и двух стилей. На выборку приходится шесть запросов с названиями жанра и стиля и шесть с заменами из учебного словаря. Нормализованные тексты между частями не пересекаются. Целевые сочетания жанра и стиля повторяются по замыслу коллекции. Запросы созданы до расчёта метрик ранжирования. Этот тест позволяет проверить поиск по другим шаблонным формулировкам и макетам. Перенос на реальные запросы требует отдельной выборки.

Словарь признаков и IDF рассчитываются только по 12 train-описаниям. Для каждого слова IDF равен `ln((1 + N) / (1 + df)) + 1`. Векторы карточек и запросов строятся с этими же весами. Во втором варианте токены запроса заменяются по восьми соответствиям из словаря ЛР № 4 перед вычислением вектора. При расчёте признаков используются только `description` или `text`. Стиль, жанр, хеши, ID и геометрия служат для разметки и аудита.

Проверка утечки подставляет новые слова во все описания validation и test и сравнивает весь словарь с весами IDF. Код подготовки не выбирает модель и не рассчитывает метрики ранжирования. В ЛР № 7 вариант выбирается на validation и затем проверяется на зафиксированном test; результаты по запросам версии 1.1 сравниваются отдельно.
